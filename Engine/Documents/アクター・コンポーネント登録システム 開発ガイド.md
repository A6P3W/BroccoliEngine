# BroccoliEngine アクター・コンポーネント登録システム 開発ガイド

## 1. 概要

BroccoliEngineは、C++20で標準化されていない完全な言語リフレクションを補うため、マクロ、テンプレート、静的初期化を組み合わせた独自の型登録システムを採用しています。

主な目的は次のとおりです。

- C++型とクラス名文字列を関連付ける
- 文字列からActorを生成する
- エディタのクラス一覧を自動構築する
- JSONレベルファイルからActorを復元する
- Actorごとに一意のインスタンス名を割り当てる

## 2. Actorクラスの定義

### 2.1 `DEFINE_ACTOR_CLASS(ClassName)`

Actor派生クラスのヘッダー内に記述します。

```cpp
#pragma once

#include "Actor.h"

class ADoorActor : public AActor {
 public:
  DEFINE_ACTOR_CLASS(ADoorActor)

  ADoorActor();
};
```

このマクロは、少なくとも次の型情報APIをクラスへ追加します。

- `StaticClassName()`：インスタンスを生成せずクラス名を取得
- `GetActorClassName()`：仮想関数経由で実インスタンスのクラス名を取得

型名は登録、保存、ロード、デバッグ表示、Automation APIなどで共通識別子として利用されます。

### 2.2 Componentクラス

ActorComponent派生クラスでは、対応するComponent用マクロを使用します。

```cpp
class MHealthComponent : public MActorComponent {
 public:
  DEFINE_ACTOR_COMPONENT_CLASS(MHealthComponent)

  MHealthComponent();
};
```

Componentのクラス名は、ネットワークComponent識別、Automation公開、デバッグ情報などに使用できます。

## 3. Actorの自動登録

### 3.1 `REGISTER_ACTOR(ClassName)`

Actor実装ファイルのグローバル領域へ記述します。

```cpp
#include "DoorActor.h"

REGISTER_ACTOR(ADoorActor)

ADoorActor::ADoorActor() = default;
```

内部的には、`TActorAutoRegister<ClassName>` の静的オブジェクトが生成されます。プログラムまたはDLLの初期化時にそのコンストラクタが実行され、`ActorRegistry`へFactoryが登録されます。

概念的な展開は次の形式です。

```cpp
static TActorAutoRegister<ADoorActor> AutoRegister_ADoorActor;
```

### 3.2 `REGISTER_GAME_MODE(ClassName)`

GameMode派生クラスには専用マクロを使用します。

```cpp
#include "BattleGameMode.h"

REGISTER_GAME_MODE(ABattleGameMode)
```

GameModeは通常Actor一覧とは別のGameModeクラス一覧にも登録されます。エディタやレベルメタデータからGameModeを選択・復元するために使用されます。

## 4. ActorRegistry

`ActorRegistry`は、クラス名と生成関数を対応付けるグローバルなスポーンFactoryです。

### 4.1 文字列からの生成

```cpp
AActor* Actor = ActorRegistry::GetInstance().Spawn(
    WorldPtr,
    "ADoorActor",
    FVector2D{100.0f, 200.0f},
    FRotator{0.0f}
);

if (Actor == nullptr) {
  // 未登録クラス、またはクラス名の誤り
}
```

登録されたFactoryは、最終的に対象Worldの `SpawnActor<T>()` を呼び出します。

### 4.2 登録状態の確認

```cpp
ActorRegistry& Registry = ActorRegistry::GetInstance();

bool bRegistered = Registry.Contains("ADoorActor");
const auto& ActorClasses = Registry.GetClassNames();
const auto& GameModeClasses = Registry.GetGameModeClassNames();
```

### 4.3 レベルロードとの関係

レベルデータにはActorのクラス名が保存されます。
未登録クラスは生成できません。レベルへ保存するActorは必ず `REGISTER_ACTOR` または `REGISTER_GAME_MODE` で登録してください。

## 5. InstanceNameの自動採番

### 5.1 基本動作

Actor生成時に明示的な名前がない場合、ActorManagerがクラス名を基準に一意名を割り当てます。

```text
AForceFieldActor_1
AForceFieldActor_2
AForceFieldActor_3
```

採番はWorld内のInstanceNameテーブルを参照し、既存名と衝突しない番号まで進めます。

### 5.2 名前の利用

InstanceNameは次の用途に適します。

- エディタのアウトライナ表示
- Automation/MCPからのActor指定
- JSONレベルデータの復元
- ログやデバッグ表示
- 実行中Actorの検索

## 6. 新規Actor追加手順

1. `AActor` または派生クラスを継承する
2. ヘッダーへ `DEFINE_ACTOR_CLASS` を追加する
3. `.cpp` のグローバル領域へ `REGISTER_ACTOR` を追加する

```cpp
// MovingPlatform.h
#pragma once
#include "Actor.h"

class AMovingPlatform : public AActor {
 public:
  DEFINE_ACTOR_CLASS(AMovingPlatform)
  AMovingPlatform();
};
```

```cpp
// MovingPlatform.cpp
#include "MovingPlatform.h"

REGISTER_ACTOR(AMovingPlatform)

AMovingPlatform::AMovingPlatform() = default;
```

## 7. 注意事項

- 同じクラスを複数の翻訳単位で登録しないでください。
- クラス名文字列を変更すると、既存レベルデータとの互換性が失われます。
- Worldに干渉する処理を登録コンストラクタへ追加しないでください。
