# BroccoliEngine リソースパス仕様書・開発ガイド

BroccoliEngine では、実行環境（エディタ実行 / パッケージ版実行）や開発環境の違いを吸収し、アセット・レベルファイルの可搬性を高めるために仮想パス表記**を採用しています。

---

## 1. バーチャルパス（仮想パス）の基本規則

BroccoliEngine 内でリソース（テクスチャ、フォント、レベルファイル、音声等）を指定する際は、原則として以下の**バーチャルパス（`/`で始まるプレフィックス付きパス）**を使用します。

| 仮想プレフィックス | 用途 | 指定例 |
| :--- | :--- | :--- |
| **`/Engine/`** | エンジン共有のリソース（デフォルトテクスチャ、標準フォント、エディタ用UI等） | `/Engine/texture_Checker_64px.png`<br>`/Engine/NotoSansJP-Regular.ttf` |
| **`/Game/`** | 現在のゲームプロジェクト固有のリソース（レベル、ゲーム用画像、BGM等） | `/Game/LevelStarter.BLevel`<br>`/Game/Textures/Player.png` |

### 補足規則
- **スラッシュ表記の統一**: パス区切り文字には Windows 環境であっても常に正スラッシュ `/` を使用します。
- **明示的な仮想パス**: `/Engine/`、`Engine/`、`/Game/`、`Game/` で始まるパスだけが仮想パスとして展開されます。
- **通常の相対パス**: 仮想プレフィックスを持たないパス（例: `Resources-EOS/Stage1/Stage1.BLevel`）は、自動的に `/Game/` を付与せず、現在の作業ディレクトリからの相対パスとして保持されます。

## 2. 実行環境ごとの物理パス展開（`PathResolver::Resolve`）

C++ コード上で `PathResolver::Resolve("パス")` が呼び出されると、明示的な仮想パスは現在のビルド構成（`Editor` または `Debug`/`Release` ランタイム）に応じた物理パスへ展開されます。通常の相対パスは正規化だけを行い、そのまま返されます。

### `Resolve` の戻り値

| 入力パス | エディタビルド (`_EDITOR`) | パッケージ/ランタイムビルド (`_DEBUG` / `_RELEASE`) |
| :--- | :--- | :--- |
| **`/Engine/foo.png`** | `<EngineSourceDir>/Resources/foo.png` | `Resources/Engine/foo.png` |
| **`/Game/bar.png`** | `<ProjectRoot>/<GameName>/Resources/bar.png` | `Resources/<GameName>/bar.png`<br>*(例: `Resources/MyGame/bar.png`)* |
| **`Resources-EOS/foo.png`** | `Resources-EOS/foo.png` | `Resources-EOS/foo.png` |

> **ポイント:** C++ コード内やレベルファイル内で `/Game/LevelStarter.BLevel` と記述しておけば、エディタ上で実行してもビルド後の配布パッケージ（`Publish/`）で実行しても、エンジンが自動的に正しいファイルを参照します。

通常の相対パスは `PathResolver::Resolve` からそのまま返され、実際の参照先はプロセスの作業ディレクトリによって決まります。Editor の作業ディレクトリは `<ProjectRoot>/<GameName>` に設定されるため、上記の例は `<ProjectRoot>/<GameName>/Resources-EOS/foo.png` を参照します。Debug/Release では実行スクリプトやデバッガーの作業ディレクトリをランタイム出力ルートへ設定してください。この場合は `<RuntimeRoot>/Resources-EOS/foo.png` を参照します。

## 3. レベルファイル（.BLevel / .BLevel.json）の仕様

BroccoliEngine のレベルファイルには、開発用の JSON ソースと暗号化されたランタイム成果物の 2 種類が存在します。

| 拡張子                | フォーマット | 用途                                                                  |
| :----------------- | :----- | :------------------------------------------------------------------ |
| **`.BLevel.json`** | JSON   | **開発用ソースファイル**。エディタでの保存時や、手動編集用。                                    |
| **`.BLevel`**      | バイナリ   | **ランタイム用ビルド成果物**。`broccoli_build` や `ConvertLevels.py` によって自動生成される。 |

### `SceneManager::OpenLevelByPath` の自動フォールバック
`SceneManager::OpenLevelByPath("/Game/LevelStarter.BLevel")` のようにパスを指定した場合、`SceneManager` 内のパス解決処理（`ResolveRuntimeLevelPath`）は以下の順序でファイルを探索します：

1. 指定されたパス (`.../LevelStarter.BLevel`) が存在するか確認
2. 存在しない場合、拡張子を `.BLevel.json` に置き換えたファイル (`.../LevelStarter.BLevel.json`) が存在するか確認
3. 存在する方を自動的に読み込む

そのため、**コード上や呼び出し時は常に `.BLevel` 拡張子を指定しておけば、未変換の `.BLevel.json` が置かれている開発環境でも正常にロード**されます。

## 4. C++ でのパス操作 API

`PathResolver` クラス（`EngineCore/Utils/Public/PathResolver.h`）が提供する主要な静的メソッドです。

普段のゲーム開発（既存コンポーネントの利用）では**触る必要はありません。**

### 直接呼ぶケースは2つだけ

#### 1. `Resolve()` を使うとき（ファイルを直接開く・確認する）
C++標準機能でファイルを開いたり、存在確認をするときに使います。
```cpp
// C++の std::ifstream で独自JSONを開く
std::string realPath = PathResolver::Resolve("/Game/Data/Enemy.json");
std::ifstream file(realPath);

// ファイルの存在チェックをする
bool exists = std::filesystem::exists(PathResolver::Resolve("/Game/Data/Enemy.json"));
```

#### 2. `SanitizeResourcePath()` を使うとき（絶対パスを保存用に変換する）
OSダイアログで選んだ絶対パス（`C:/...`）を、セーブデータやJSONに保存するときに使います。
```cpp
// ダイアログで選んだ絶対パスをバーチャルパスに変換
std::string absolutePath = FileDialog::OpenFile(...); 
std::string virtualPath = PathResolver::SanitizeResourcePath(absolutePath);

// リソースルート外のパス（変換失敗し絶対パスのまま）の場合は保存を拒否またはエラー処理を行う
if (virtualPath.rfind("/Game/", 0) == 0 || virtualPath.rfind("/Engine/", 0) == 0) {
    saveData["Texture"] = virtualPath;
} else {
    // エラーハンドリング（ルート外のファイルが選択された場合）
}
```

## 5. 開発時の注意事項

1. **絶対パスのハードコード禁止**
   - 絶対パスを C++ コードやアセットに埋め込まないでください。
1. **相対パスと仮想パスの使い分け**
   - Editorとランタイムで配置が変わるゲーム・エンジン資産には `/Game/` または `/Engine/` を使用してください。
   - 作業ディレクトリからの配置が共通するファイルに限り、通常の相対パスを使用してください。
1. **OS ダイアログや外部ツールのパス受け取り時**
   - `FileDialog::OpenFile()` などで OS の標準ファイルダイアログから絶対パスを取得した場合は、バーチャルパスに変換してから保存・保持してください。
1. **MCP (Model Context Protocol) / 自動化サーバー経由でのレベル指定**
   - MCP Toolや Automation API からレベルを開く際、`OpenLevelByPath` に渡されるパスは `/Game/` または `/Engine/` 配下のみが許可され、`..` を含む相対パス（パス・トラバーサル）やそれら以外の絶対パスは検証により拒否されます。
